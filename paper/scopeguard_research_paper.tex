\begin{abstract}
The rapid integration of Large Language Model (LLM)-powered autonomous agents into cloud management workflows promises to automate complex infrastructure-as-code (IaC) provisioning, resource scaling, and operational monitoring. However, deploying off-the-shelf AI agents with static cloud credentials introduces severe security risks: agents granted broad Identity and Access Management (IAM) permissions can exhibit unintended scope creep, succumb to prompt injection attacks, or execute destructive actions without deterministic identity attribution. Traditional access control models—such as static Role-Based Access Control (RBAC) and declarative Policy-as-Code engines (e.g., OPA, AWS Cedar)—fail to dynamically infer permission boundaries from natural language task objectives prior to execution. We present \textbf{ScopeGuard}, an asynchronous, identity-scoped proxy framework designed for real-time permission authorization and execution control of AI agents in cloud infrastructure. ScopeGuard intercepts outbound agent tool calls, attaches cryptographically verifiable identity metadata (Agent ID, Session UUID, declared task, and reasoning chain), and dynamically compiles a task-aware permission scope using a rule-based action taxonomy. Intercepted API calls are evaluated against this computed scope under a fail-closed policy engine supporting three ablation operational modes (\textit{passthrough}, \textit{tagging\_only}, and \textit{full}). We empirically evaluate ScopeGuard across a benchmark suite of 200 infrastructure management tasks (100 legitimate operations and 100 adversarial/off-scope attacks across 10 security threat categories). In \textit{full} enforcement mode, ScopeGuard achieves an overall accuracy of \textbf{89.0\%}, a scoping precision of \textbf{97.8\%}, an adversarial block rate of \textbf{88.0\%}, and a false positive rate of \textbf{2.0\%} on legitimate tasks, while introducing a minimal average latency overhead of \textbf{108.9 ms}—well within the 200 ms real-time inference budget. We validate live execution against real Amazon Web Services (AWS) infrastructure endpoints including Amazon RDS, EC2, S3, and CloudWatch.
\end{abstract}

\section{Introduction}
Cloud infrastructure environments are the foundation of modern digital computing, relying on complex control planes to manage compute instances, relational databases, object storage, and network topologies \cite{ayers2018}, \cite{jiang2026}. Managing these resources requires executing multi-step infrastructure operations via Cloud APIs (e.g., AWS SDK \texttt{boto3}), Infrastructure-as-Code (IaC) CLI tools (e.g., Terraform), and CI/CD pipelines (e.g., GitHub Actions). As enterprise cloud architectures expand in scale and heterogeneity, human operators struggle to keep pace with manual provisioning and operational maintenance \cite{hadary2020}.

Recent advances in agentic AI offer a compelling solution. Autonomous AI agents—LLM-based systems capable of goal reasoning, multi-step planning, and tool invocation \cite{schick2023}, \cite{yao2023}—are increasingly deployed to automate cloud administration, database scaling, and incident response workflows \cite{hong2024}, \cite{yang2024}. 

However, delegating cloud execution authority to autonomous agents introduces critical security and governance vulnerabilities:
\begin{enumerate}
    \item \textbf{Lack of Dynamic Task Scoping (\textit{Not Least-Privileged})}: Standard cloud IAM assigns static roles to service principals or execution environments. To enable an agent to perform diverse tasks, operators frequently grant broad administrative roles (e.g., \texttt{AdministratorAccess} or wildcard \texttt{s3:*}). Consequently, an agent instructed to "check database status" retains permission to terminate production instances or modify IAM security groups.
    \item \textbf{Vulnerability to Indirect Prompt Injection (\textit{Not Protected})}: Autonomous agents process untrusted external data (e.g., application log files, git commit messages, or web scraping inputs). Adversaries can inject malicious instructions into these inputs, coercing the agent into executing off-scope or destructive commands \cite{shavit2023}.
    \item \textbf{Absence of Session-Level Identity Attribution (\textit{Not Attributable})}: Standard Cloud API logs (e.g., AWS CloudTrail) record only the static IAM role assumed by the agent container. They fail to bind individual API calls to specific agent instances, session UUIDs, declared user objectives, or underlying LLM reasoning chains.
\end{enumerate}

\subsection{Key Contributions}
We introduce \textbf{ScopeGuard}, a dynamic policy proxy and identity attribution engine positioned between AI agent tool-use interfaces and cloud infrastructure backend APIs. This paper makes the following primary contributions:
\begin{itemize}
    \item \textbf{Formal Architectural Framework}: An asynchronous proxy combining identity tagging, rule-based permission compilation, fail-closed policy enforcement, and persistent SQLite audit logging.
    \item \textbf{Dynamic Task-to-Scope Compiler}: A deterministic classifier operating over a structured cloud action taxonomy that maps natural language task prompts to explicit AWS/IaC action scopes with implicit read-grant inheritance.
    \item \textbf{Empirical Ablation Benchmark}: A 200-task evaluation benchmark (100 legitimate operations and 100 adversarial attacks across 10 security threat categories) evaluated across three operational modes (\textit{passthrough}, \textit{tagging\_only}, and \textit{full}).
    \item \textbf{Live AWS Validation}: Real-time execution against live AWS endpoints (Amazon RDS, EC2, S3, CloudWatch) demonstrating an \textbf{88.0\% adversarial block rate} and \textbf{97.8\% scoping precision} with \textbf{108.9 ms latency overhead}.
\end{itemize}

\section{Background and Motivation}

\subsection{Cloud Infrastructure Control Planes \& IAM Limits}
Cloud control planes manage compute, storage, database, and networking resources via RESTful API endpoints. Traditional IAM assumes human developers configure static permissions for predictable microservices. AI agents exhibit non-deterministic decision paths. Static IAM policies assigned to agents must either be over-provisioned (exposing cloud environments to prompt injection) or under-provisioned (causing legitimate agent task failures).

\subsection{Policy-as-Code Engine Deficiencies}
Policy-as-Code frameworks such as Open Policy Agent (OPA) and AWS Cedar evaluate declarative rules. However, OPA and Cedar require human policy authors to manually pre-write rules for every resource ARN and action string. They lack the semantic capacity to interpret an agent's natural-language task prompt prior to authorization.

\subsection{Content Guardrails vs. API Authorization}
Safety frameworks such as NVIDIA NeMo Guardrails and Lakera Guard filter prompt text generations. However, content guardrails operate outside the execution path of structured API calls. They cannot inspect JSON parameter payloads sent to \texttt{boto3} or Terraform CLI to verify if a specific API parameter matches the authorized scope.

\section{ScopeGuard System Architecture}

ScopeGuard functions as an intercepting reverse proxy between an AI Agent execution environment and cloud infrastructure backends (AWS SDK, LocalStack, Terraform CLI, GitHub Actions).

\subsection{Component Breakdown}
\begin{enumerate}
    \item \textbf{Identity Tagger}: Generates a unique UUID4 tracking ID per call, binding Agent ID, Session ID, declared task description, timestamp, and reasoning chain. Applies regex redaction to strip credentials from parameter logs.
    \item \textbf{Task-to-Scope Classifier}: Tokenizes the agent's declared task string and matches action keywords across resource modules (S3, EC2, IAM, RDS, CloudWatch, Lambda), resolving implicit read grants.
    \item \textbf{Policy Engine}: Evaluates requested tool actions against computed scopes under three modes (\textit{passthrough}, \textit{tagging\_only}, \textit{full}) under a fail-closed paradigm.
    \item \textbf{SQLite Audit Logger}: Asynchronously persists structured \texttt{AuditEntry} records in an indexed database.
    \item \textbf{Backend Executor}: Dispatches authorized calls to LocalStack or live AWS endpoints in \texttt{us-east-1}.
\end{enumerate}

\section{Formalization and Algorithmic Design}

Let $\mathcal{A}$ denote the set of all valid Cloud API actions defined in the system taxonomy. An incoming tool request $Q$ is defined as a tuple:
\begin{equation}
Q = \langle \text{agent\_id}, \text{session\_id}, T_{\text{decl}}, a_{\text{req}}, P \rangle
\end{equation}
where $T_{\text{decl}}$ is the natural language task string, $a_{\text{req}} \in \mathcal{A}$ is the requested API action, and $P$ is the parameter dictionary.

\begin{algorithm}[H]
\caption{Compute Task Scope}
\label{alg:classifier}
\begin{algorithmic}[1]
\REQUIRE Declared task string $T_{\text{decl}}$, Taxonomy schema $S$
\ENSURE ScopeResult containing $S_{\text{allowed}}$, risk level $R$
\STATE $Tokens \leftarrow \text{TokenizeAndStem}(T_{\text{decl}})$
\STATE $S_{\text{allowed}} \leftarrow \emptyset$
\FOR{each $res\_type \in S.\text{resource\_types}$}
    \FOR{each $action, meta \in res\_type.\text{actions}$}
        \FOR{each $kw \in meta.\text{keywords}$}
            \IF{$kw \in T_{\text{decl}}.\text{lower}()$}
                \STATE $S_{\text{allowed}} \leftarrow S_{\text{allowed}} \cup \{action\}$
            \ENDIF
        \ENDFOR
    \ENDFOR
\ENDFOR
\IF{$S.\text{meta\_rules}.\text{implicit\_read\_grant}$ is True}
    \FOR{each $action \in S_{\text{allowed}}$}
        \IF{$\text{IsWriteOperation}(action)$}
            \STATE $S_{\text{allowed}} \leftarrow S_{\text{allowed}} \cup \text{GetImplicitReadActions}(action)$
        \ENDIF
    \ENDFOR
\ENDIF
\RETURN $\langle S_{\text{allowed}}, R \rangle$
\end{algorithmic}
\end{algorithm}
